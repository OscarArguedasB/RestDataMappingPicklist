# Privacy policy

REST Data Mapping Picklist is an Azure DevOps extension. It runs entirely in the browser of the person using Azure DevOps. The publisher runs no servers for it and collects no telemetry, analytics or personal data.

## What the extension sends, and where

- **To the REST APIs your administrators configure.** When someone opens the list on a work item, their browser calls the configured endpoint directly. The request can include work item field values that the configuration inserts into the URL or parameters, and the configuration’s sign-in details: a user name and password, a token, an API key, or an OAuth 2.0 access token. Cookies are never sent. How those services handle the data is governed by their own privacy policies.
- **To the token URL of an OAuth 2.0 configuration.** Before it calls the API, the browser requests an access token from the token URL the configuration names. The request carries the client ID, the client secret or a token signed with the configuration’s private key, and the scope and other parameters the configuration sets. The access token that comes back is kept in that page’s memory only and sent only to the API. The setup page’s test does the same from the administrator’s browser.
- **To Azure DevOps.** The extension reads and writes work item fields through the work item form; reads processes and work item type layouts; updates REST Picklist controls in process layouts when an administrator assigns a configuration to them, moves them or cleans them up; reads and saves configurations, their credentials and the security policy in the extension’s data; and, on the setup page, asks Azure DevOps which permissions the signed-in person has. These calls go to your own Azure DevOps organization, as the signed-in person.
- **Nothing is sent to the publisher** or to any other service.

- Access tokens and credentials are kept in the page’s memory only, never in browser storage, and never written to logs or error messages.
- On the setup page, a certificate or key file is read in the browser. Only the private key and the certificate’s details (subject, issuer, validity and thumbprints) are saved, never the file or its password.
- Exported configuration files never contain credentials or user names.
- The setup page remembers the process you chose and which sections you opened, in the browser’s session storage.

## Your choices

- Administrators decide which APIs and token services the extension calls and what data goes to them, and can limit endpoints and sign-in methods with the security policy.
- Uninstalling the extension stops all of the above. What the extension saved in your organization (configurations, credentials and the security policy) and the settings in process definitions can remain until you remove them, so delete configurations on the setup page first to remove their credentials.
